A focused, beginner-friendly repository for learning Data Structures & Algorithms (DSA) through LeetCode problems. Each file contains problem statements, one or more Java solutions, complexity analysis, and lessons learned. Designed to help new learners build consistent practice habits, understand patterns, and progress from easy → medium → hard problems.


Who this is for



- Absolute beginners starting DSA and LeetCode

- Learners who prefer reading short explanations + clean Java snippets

- Those who want a guided study plan and practical problem patterns



Repository structure (what to look for)



- Problem writeups: per-problem Markdown files (e.g., 2011.md) with code, analysis, and takeaways

- Daily_Learnings.md: daily journal of solved problems and notes

- Important_Concept.md: reusable patterns and algorithm notes

- Fucking_Documentation.md: learning reflections and tips



Getting started (quick)



1. Pick a topic (arrays, strings, linked lists, etc.).

2. Start with Easy problems for that topic; read the writeup and run the code locally.

3. After 20–30 problems, review Important_Concept.md and identify recurring patterns.

4. Gradually add Medium problems; revisit fundamentals if stuck.



Suggested 8-week roadmap



- Weeks 1–2: Arrays, Strings, Two-pointers — 3–5 problems/day

- Weeks 3–4: Hashing, Sorting, Sliding Window — 2–4 problems/day

- Weeks 5–6: Linked Lists, Stacks, Queues, Recursion — 2–3 problems/day

- Weeks 7–8: Trees, Binary Search, Graph basics — 1–2 problems/day + review

Adjust pace to maintain learning and retention.



How to read a problem file



- Problem statement & ID

- One or more implementations (clear Java code)

- Time & space complexity

- Approach / step-by-step reasoning

- Edge cases and test ideas

- What I learned — short reflections



Running Java snippets locally



- Save solution as Solution.java (or match class name)

- Compile: javac Solution.java

- Run (if a main is present): java Solution

- For LeetCode-style functions, use a local test harness or paste into LeetCode editor



Study habits & solving tips



- Understand the pattern before coding; don’t rush to implement.

- Write clean, readable code with meaningful variable names.

- Always state time and space complexity.

- Start with brute force if stuck, then optimize.

- Use small examples and hand-simulate before running.

- Keep a daily journal (like Daily_Learnings.md) to track progress and weak topics.



Conventions used in this repo



- Java solutions with clear method signatures

- Complexity annotated after each approach

- File names include problem ID where possible

- Short comparisons between multiple approaches when helpful



How to contribute
