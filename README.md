# Common Mistakes I've Learned From

Some of the mistakes I've encountered while learning Java and DSA include:

### Java Syntax

* Confusing `String` and `char`
* Confusing `String[]` and `String`
* Using `charAt()` on the wrong type
* Confusing `length` and `length()`
* Comparing `String` and `char`
* Returning the wrong data type
* Confusing `List<Integer>` and `ArrayList<Integer>`
* Forgetting Java is case-sensitive

### Problem-Solving

* Coding before understanding the problem
* Using a loop when a direct calculation is enough
* Overcomplicating simple problems
* Missing edge cases
* Not checking constraints
* Focusing on code instead of the underlying pattern
* Not manually testing the logic
* Jumping to optimization before understanding brute force

These mistakes are part of the learning process and are documented instead of hidden.

# Important Patterns I've Learned

One of the biggest goals of this repository is to stop thinking about every problem as completely new.

Some patterns I've started recognizing:

### Running Sum

```text
current value
+
previous accumulated value
```

### Maximum Value

```text
start with minimum/first value
        ↓
compare every element
        ↓
update maximum
```

### String Traversal

```text
String
  ↓
charAt(i)
  ↓
process each character
```

### Frequency / Hashing

```text
Element
   ↓
HashMap / HashSet
   ↓
Store / Count / Lookup
```

### Two Pointers

```text
left →        ← right
```

These patterns become increasingly important as problems become harder.

# How I Approach a New Problem

Before writing code, I try to answer:

### 1. What exactly is the problem asking?

Don't code immediately.

### 2. What are the inputs and outputs?

Understand the data types and constraints.

### 3. Can I solve it manually?

Take a small example.

### 4. What is the brute-force solution?

Even if it's slow, understand it first.

### 5. Is there a pattern?

Ask:

* Can hashing help?
* Can sorting help?
* Can two pointers help?
* Can a stack help?
* Can binary search help?
* Can I avoid repeated work?

### 6. What is the complexity?

Always think about:

```text
Time Complexity
Space Complexity
```

### 7. What are the edge cases?

Test unusual inputs before considering the problem finished.

# The Philosophy Behind This Repository

DSA can feel overwhelming in the beginning.

There are hundreds of concepts, thousands of problems, and countless different approaches.

But you don't need to know everything at once.

Start small.

Solve one problem.

Make a mistake.

Understand why you made it.

Solve another one.

Eventually, patterns start appearing.

And problems that once looked completely different start looking familiar.

> **Don't memorize the solution. Learn how to find the solution.**
