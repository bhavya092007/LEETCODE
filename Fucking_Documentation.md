# 🚀 My LeetCode Journey — From Confusion to Confidence

## The Beginning

When I started solving LeetCode problems, I thought the biggest challenge would be finding the solution.

But slowly I realized something:

> The hardest part was not solving the problem. The hardest part was teaching my brain to think like a programmer.

I knew programming concepts, but converting those concepts into working code was a completely different skill.


---

# My Initial Struggles

In the beginning, I made many small mistakes.

Some mistakes looked very basic:

- Confusing `length` and `length()`.
- Forgetting the difference between `char` and `char[]`.
- Using `==` for String comparison instead of `.equals()`.
- Returning the wrong data type.
- Creating arrays with incorrect syntax.
- Understanding the logic but struggling to write the code.


At that time, these mistakes felt frustrating.

I used to think:

"Why can't I write this simple code even when I understand the answer?"


Later I realized:

These small mistakes are not failures.

They are signs that my brain is learning a new language.


---

# Learning To Think In Patterns

At first, every LeetCode problem looked completely different.

But after solving many problems, I started noticing patterns.


## Array Traversal

I learned that many problems start with:

```java
for(int i = 0; i < arr.length; i++)
{

}
```


The loop itself was not the solution.

The important thing was understanding:

"What am I visiting?"



---

# Strings Were Difficult At First

Strings looked simple, but they taught me many lessons.

I learned:

A String is not just text.

It has:
- Characters
- Positions
- Indexes


Example:

```java
String s = "hello";

s.charAt(0);
```

gives:

```
h
```


I learned how to:

- Traverse characters.
- Count characters.
- Search inside strings.
- Rearrange strings.


---

# The Importance of Small Mistakes

One of my biggest lessons was:

> Never ignore small mistakes.

A single mistake like:

```java
str.length
```

instead of:

```java
str.length()
```

can stop the entire program.


But every error message teaches something.

Every debugging session builds experience.


---

# Understanding Index Mapping

One of the biggest concepts I learned was mapping.


For example:

A problem may say:

"Move each character to another position."


Initially, I struggled.

But then I learned this pattern:

```java
answer[newPosition] = value;
```


This idea is bigger than one problem.

It appears in:

- Rearranging arrays.
- Sorting based on indexes.
- Position-based problems.

# My Advice To Beginners

If you are starting LeetCode:

## 1. Do Not Rush To Medium Problems

Easy problems are not easy when you are building your thinking ability.


## 2. Write Down Mistakes

Your mistakes are your personal roadmap.


The things you struggled with today will become your strengths tomorrow.


## 3. Understand The Logic Before Code

First ask:

```
What is the problem asking?
What data do I have?
What should I return?
```


Then think about syntax.


## 4. Do Not Compare Yourself With Others

Someone may solve a problem in 5 minutes.

Someone else may need 2 hours.

Both are learning.


The goal is not speed.

The goal is improvement.
